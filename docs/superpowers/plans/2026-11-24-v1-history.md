# P5 History & Restart Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the empty `HistorySource` stub with a real, bounded, read-only artifact-tree scan so persisted workers surface marked **not live** on every viewer connect and after an OMP restart.

**Architecture:** A new `src/extension/history/` module scans `~/.omp/agent/sessions/<encoded-cwd>/<ts>_<session-id>/<worker-id>.jsonl`, maps each direct task-worker transcript to a `WorkerSnapshot{historical:true}`, and merges live-wins against the roster. The extension activation owns the one source and feeds its merged output to the bridge's existing `opts.history` seam (every `hello`) and to topology's existing `onHistoryPresent` hook (startup auto-open). The viewer (P3) and topology (P4) already consume history fully — this plan only produces it and wires it.

**Tech Stack:** TypeScript, Bun (`bun:test`, `Bun.spawn`, `node:fs`), Zod-free pure parsing (JSONL is trusted-local, fail-soft), Biome, tsc.

**Spec:** `docs/plans/specs/phase-05-history-spec.md` (requirements P5-R1..R10; interfaces `HistorySource`/`HistoryScan`/`mergeLiveAndHistorical`/`transcriptRefFor`). Verified artifact facts: `docs/analysis/phase-0-probe-report.md` (Follow-up probe 2026-11-24).

## Global Constraints

- Read-only: the scanner NEVER writes to OMP session dirs, NEVER acquires a lease, NEVER runs `omp session` attach/transfer, NEVER constructs `omp read history://<id>` (P5-R5/R10, F-11/RC-15, V-OMP-7).
- Local-only: no network access; any lens cache lives under a `0700` dir / `0600` files (P5-R10, NFR-01).
- Fail-soft: a scan failure yields partial results + one `notice`, never a thrown error into an OMP turn (NFR-02, FR-12, P5-R1/R7).
- Fire-and-forget: the scan runs async off the OMP turn path; activation never awaits it on a handler (F-15, P5-R8).
- `PROTOCOL_VERSION` stays `1`; `historical` and `hello.history` are additive optional fields already present in `src/protocol/types.ts` (RC-3). Do not change the protocol.
- Live wins on `id` collision; historical duplicates dropped (P5-R3).
- Honest status: terminal JSONL markers map to `completed`/`failed`/`aborted`; no terminal marker → `aborted`; live counters that cannot be reconstructed stay **absent**, never zero-filled (P5-R4, R-04).
- Caps default `maxSessions=20`, `maxWorkers=100`, `maxFileBytes` per-transcript probe; mtime-keyed cache avoids reparse (P5-R8, NFR-03).
- Gate: scanner inert outside Herdr (the activation gate already returns early; the scan is only invoked from activation) (P5-R10, FR-01).
- Tests fixture-driven and deterministic — no wall-clock soaks (D5).
- Verify commands: `bun test` (full suite), `bun test tests/extension/history/` (module), `bun run typecheck`, `bun run lint`.

## Review Focus

1. **Lease/control creep** — a historical render path that secretly runs `omp session attach`/`transfer` or `omp read history://` would hang host-less or hijack a session; the no-lease/no-`history://` tamper test must fail if introduced (P5-R5).
2. **Live-wins violation** — a historical row overwriting or duplicating a live worker breaks FR-14/RC-3; the merge tamper test must fail if the historical row survives a collision (P5-R3).
3. **Fabricated counters** — zero-filling or guessing live counters for a dead worker lies to the user (R-04); the honest-status test must fail if counters appear on a historical entry (P5-R4).
4. **Torn-read throw** — a live TUI flushing a half-written trailing JSONL line must not throw into the OMP turn; the torn-line test must fail if an exception propagates (P5-R7, U-OMP-7).
5. **Nested/foreign leakage** — a depth-≥2 nested worker or another cwd's worker appearing as a top-level row breaks FR-10; the direct-only filter test must fail if a nested/foreign entry is surfaced (P5-R1).

### Task 2: Honest status mapping + merge + transcript.ref

**Interfaces:**

- Produces:
  - `mapTerminalStatus(lines: ParsedLine[]): WorkerStatus` — scan for the last `{type:"custom",customType:"session_exit",data:{kind,reason}}`: `kind:"normal"` → `completed`; `kind:"signal"` → `aborted`; an explicit error/failed terminal marker → `failed`; no terminal marker → `aborted`.
